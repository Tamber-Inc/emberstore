emberstore binary, byte by byte

Each example below is a real C++ value encoded by Calder::toBinary. Every byte is labelled by walking the result with Calder's own decoder (parseValueHeader, ByteReader, ObjectEntryCursor). Hover a byte to see what it is and why it is there; click to keep it selected. Click a value in the tree to see all of its bytes.

The format in brief 
file      := "CLD1" | u32 keyTableOffset | value | keyTable
keyTable  := varint keyCount | { varint length | bytes }*
value     := tag byte | payload

Null / False / True   no payload
Int          zigzag varint
Double       8 IEEE-754 bytes
Float32      4 bytes, when the double survives float
String       varint byteLength | UTF-8 bytes
Object       u32 payloadSize | { varint keyId | value }*
Map          u32 payloadSize | { varint keyLength | bytes | value }*
Array        u32 payloadSize | u32 count | value*
PackedFloat  u32 count | count × 4 bytes
PackedDouble u32 count | count × 8 bytes
PackedInt32  u32 payloadSize | u32 count | zigzag varints
PackedInt64  u32 payloadSize | u32 count | zigzag varints
  • u32: 4 bytes, little-endian, so the lowest byte comes first: 5d 00 00 00 is 93.
  • varint: 7 bits of the number per byte, lowest bits first. A byte's top bit is 1 when another byte follows. Numbers below 128 take one byte.
  • zigzag: signed numbers are mapped to unsigned ones before the varint (0→0, −1→1, 1→2, −2→3), so small negative numbers stay one byte.
  • payloadSize counts the bytes after the size field itself, so a reader can jump over a whole container.
  • Field names are stored once, in the key table at the end. Each field stores only its key id.
  • Packed arrays (vectors of float, double, int, int64_t) have no tag per element. Other vectors tag every element.
